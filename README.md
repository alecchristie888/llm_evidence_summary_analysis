# Faithfulness rewards omission in AI synthesis of conservation evidence

Code and data for Agrawal, Jaffer, Reynolds, Cutts, Dicks, Madhavapeddy, Smith, Sutherland, Taylor, Thornton & Christie (in preparation).

The study benchmarks four frontier LLMs (Claude Sonnet 4, Gemini 2.5 Pro, GPT-5, Kimi K2) that each had to find and summarise evidence from the Conservation Evidence database through an agentic search loop, for 520 open-ended questions across 19 subject areas. The 1,991 resulting summaries (23,641 statements) were scored for relevance, citation correctness and faithfulness by a judge LLM validated against 820 expert-labelled statements, and retrieval recall, precision, agent behaviour and task completion were measured from the tool-call logs.

- `MANIFEST.csv` gives the size, sha256 and record count of every data file; `python check_manifest.py` verifies a copy.
- `./run_all.sh` regenerates every derived table and figure from the archived raw files with no API calls, and ends with `verify_results.py`, which checks 85 reported numbers.
- Retrieval metrics are reported under the evaluated-run definition: recall, precision, actions opened and cite-through are computed from the tool-call trace of the run that produced each judged summary, so they share the denominator of the judge metrics. The earlier log-based definition (union over all completed runs of a question) is retained in `retrieval_definition_comparison.csv` for comparison.

## Layout

```
00_action_data_prep/      split action files by subject area, rebuild per-area inputs for question generation, token sizes
01_question_generation/   question generation (Gemini 2.5 Pro), completeness filter, canonical question table
02_summary_generation/    agentic summariser loop (OpenRouter), duplicate-run fix
02b_statement_decomposition/  split summaries into statements and extract cited action IDs (Gemini 2.5 Pro, batch API)
utils/                    shared generation code: action parsing, hybrid search index (BM25 + dense + cross-encoder), paths
03_llm_judge/             judge pipeline, prompt files, GEPA optimisation, validation against expert labels
04_retrieval_traces/      parsing of generation logs: retrieval recall/precision, behaviour, attrition
05_analysis/              all analysis: score tables and failure tags (Python), bootstrap statistics, evaluated-run retrieval
                          metrics, ranks, composite and tails (R), and a single figures.R that draws every figure
data/                     archived inputs and outputs (see data/README_data.md); bulky folders are git-ignored
outputs/figures/          regenerated figures
run_all.sh  run_all.ps1  verify_results.py  make_manifest.py  check_manifest.py  requirements-generation.txt
```

## Reproducing

Run everything from the repository root (the folder containing `run_all.sh`), with the data archive unpacked so that `data/judge_outputs/`, `data/summaries/` etc. sit directly under `data/`. Symptom of a wrong working directory or a missing archive: `build_score_tables.py` finds no judge files and `statement_level.csv` / `summary_level.csv` come out empty, after which `analysis.R` fails with `object 'summary_model' not found`. The scripts now stop with an explicit message in that case instead of writing empty tables; if you already have an empty `data/judge_outputs/merged_all_records.json` from an earlier attempt, delete it so it is rebuilt from `by_model/`.

On Windows use PowerShell and `.\run_all.ps1` (same steps, stops at the first error), or Git Bash with `bash run_all.sh 2>&1 | tee run_all.log`. Double-clicking or invoking `.\run_all.sh` from PowerShell hands the file to whatever program is associated with `.sh`, and its output and errors are lost. All Python scripts read and write files as UTF-8 explicitly, so the Windows default code page does not matter.

```
pip install pandas numpy openpyxl scikit-learn
Rscript -e 'install.packages(c("dplyr","tidyr","readr","ggplot2","stringr","forcats","purrr","tibble","scales","broom","viridisLite","jsonlite","patchwork"))'
./run_all.sh
```

Bootstrap CIs are seeded (`set.seed(42)` in `analysis.R`; `set.seed(1)` in `reframed_metrics.R`; per-figure seeds in `figures.R`; `numpy.random.default_rng(1)` in the Python retrieval scripts) and reproduce exactly when `analysis.R` is run as a fresh `Rscript` session. Re-running the judge or the summarisers (`03_llm_judge/evaluate_*.py`, `02_summary_generation/summary_gen.py`) requires an `OPENROUTER_API_KEY` environment variable, incurs API costs, and is not guaranteed to reproduce the archived outputs because hosted models change behind fixed identifiers; the archived outputs are the record.

### Re-running the generation stages (00, 01, 02, 02b)

These stages call paid APIs and are not needed to reproduce the paper's numbers. Install `requirements-generation.txt` (it pins `transformers` 4.x, which the Nomic embedding model needs), put your keys in a `.env` file (`OPENROUTER_API_KEY` for summaries; `PAID_GEMINI_API_KEY` for question generation and statement decomposition), create a `logfiles/` folder, and run each script as a module from the repository root so that `utils/` is importable:

```
python -m 00_action_data_prep.synopsis_splitter
python -m 00_action_data_prep.build_synopsis_concat
python -m 01_question_generation.question_gen_multi_action
python -m 02_summary_generation.summary_gen
python -m 02b_statement_decomposition.summary_statements_gen_BATCH
python -m 02b_statement_decomposition.cited_statements_gen_batch
```

The code is as run, except that input paths now point at `data/actions/` (set in `utils/paths.py`; override with `IGF_ACTION_DATA_DIR`). Working folders (`live_questions/`, `live_summaries/`, `batch_gen/`, `question_gen_data/`) are created relative to the repository root. `02b_statement_decomposition/clean_summary_statements.py` holds one-off housekeeping functions used between batch runs (renaming folders, resetting flags) and is not part of the method.

Checked offline in November 2026, with no API calls:
- **Search tool.** 400 randomly sampled `search_actions` calls from the archived traces (5,990 in total) were replayed through `utils/rag.py`, and every call returned the recorded action IDs in the recorded order.
- **Statement decomposition.** Re-parsing the raw Gemini batch outputs with the 02b scripts reproduced the archived cited statements for all 1,991 summaries. It also reproduced the statement lists for the 1,952 summaries whose raw output survives; for the other 39 the raw output was overwritten during a rerun.
- **Question-generation inputs.** `00_action_data_prep` rebuilds all 24 per-area input files identically to the originals.

Exact reproduction of the search tool needs two archived input folders that the original code used: the dense-embedding cache `data/actions/dense_embeddings_cache/bg_km_nomic_dense_embeddings.npy` and the key-message files `data/actions/key_messages/km_all/` that `get_action_details` returned to the models. Use the archived embedding cache rather than regenerating it. It was computed on an earlier version of the action set (3,742 actions, against 3,733 in `bg_km_all`), so a cache rebuilt from the current files would not reproduce the archived searches.

## Models and settings

All models were called through OpenRouter. Summarisers: `openai/gpt-5`, `anthropic/claude-sonnet-4`, `google/gemini-2.5-pro`, `moonshotai/kimi-k2-0905` (provider pinned to `fireworks/fp8`, `allow_fallbacks=False`); `reasoning_effort="low"`, `max_iterations=10`. Judge: Gemini 3.1 Pro Preview, temperature 0, refined manual prompts (relevance v16, citation correctness v17, faithfulness v14-concat; texts in `03_llm_judge/prompt_files/`). Candidate judges compared: Claude Opus 4.7, GPT-5.4; GEPA-optimised prompts with seeds 1234 and 5678.
